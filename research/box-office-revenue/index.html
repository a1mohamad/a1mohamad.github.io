Notebook Blueprint

Project Overview

The notebook transforms raw movie metadata into a log-revenue regression system for worldwide box office forecasting.

The core notebook, box_office_revenue.ipynb, studies the TMDB box office prediction problem from exploratory analysis through final submission generation. The target is heavily skewed, so revenue is modeled with log1p(revenue), evaluated with RMSE, and converted back to the original dollar scale with expm1 for the final test_result.csv.

Problem typeSupervised regression on movie metadata, JSON-style cast/crew fields, release timing, budget, popularity, ratings, and engineered ratios.
Data expansionThe 3,000-row competition train file is merged with 2,001 additional training rows and rating/vote features.
Production goalThe notebook is not only exploratory: its feature logic is mirrored in app code and serialized into model artifacts.

Feature Engineering

From Raw Movie Metadata to 200 Features

The pipeline combines manual corrections, JSON parsing, group statistics, one-hot fields, text counts, and ratio features.

Modeling Strategy

XGBoost, LightGBM, CatBoost Weighted Blend

Three gradient boosting engines are trained across 10 folds and blended with fixed weights.

RMSE Objective
Metric
$$RMSE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y_i})^2}$$
The notebook evaluates errors in log-revenue space, which makes huge blockbusters and small releases more comparable during optimization.
Weighted Ensemble
Blend
$$\hat{y}=0.2\hat{y}_{xgb}+0.4\hat{y}_{lgb}+0.4\hat{y}_{cat}$$
LightGBM and CatBoost receive higher weight while XGBoost contributes additional tree diversity.
XGBoost
Core booster diversityreg:squarederror, learning rate 0.1, max depth 6, subsample 0.6, column sample 0.7, histogram tree method in production training.
Weight0.20
Rounds100k
Early Stop2500
LightGBM
Fast leaf-wise learnernum_leaves=30, max depth 9, low learning rate 0.005, feature and bagging fractions at 0.9, L1 regularization 0.2.
Weight0.40
Rounds10k
Early Stop500
CatBoost
Robust boosting companion100k iterations, learning rate 0.005, depth 5, column sampling by level 0.8, RMSE evaluation, and Bayesian bagging temperature 0.2.

Notebook Execution

Training Loop, Out-of-Fold Predictions & Submission

The notebook keeps validation predictions, test predictions, fold errors, and final CSV generation in one reproducible modeling path.

Fold orchestration

Out-of-fold validation

The notebook builds a KFold(n_splits=10, shuffle=True, random_state=2025) split, then fills val_pred only at each fold's validation indices. This makes the blended validation estimate honest because each row is predicted by models that did not train on that row.

Submission path

Back to revenue scale

Since the target is trained as log1p(revenue), the final test prediction is converted with np.expm1(test_pred) before writing data/test_result.csv with the Kaggle submission columns.

val_pred = np.zeros(train.shape[0])

Inference Blueprint

Saved Artifacts and Prediction Flow

The app loads trained boosters once, aligns every request to the saved feature order, blends log predictions, and returns dollar revenue.

The production path is built around serialized artifacts in models/: final_xgb.pkl, final_lgb.pkl, final_cat.pkl, features.pkl, train_dict.pkl, global_stats.pkl, and blend_config.pkl. This keeps inference deterministic even when an incoming request is a single JSON movie instead of a full batch dataset.

Feature parityprepare_single uses saved global statistics and feature order so one movie receives the same 200-column schema as training data.
Cache pathRedis is optional. When reachable, request hashes are cached for 36,000 seconds; otherwise inference continues normally.
Output scaleModel outputs are blended in log space, then converted with np.expm1 before returning revenue.

FastAPI Mechanics

Route Validation, Error Handling & Logging

The API layer does more than call a model: it validates input mode, normalizes blanks, catches data-loading failures, and records every prediction attempt.

Batch routes

CSV upload or database table

POST /predict/movies_file accepts exactly one source: a multipart CSV file or a form field naming a PostgreSQL table. The GET version mirrors that behavior with query parameters, allowing file-path or table-based prediction from the same service.

Defensive API behavior

Clear failure modes

If both inputs are supplied, or neither is supplied, the route returns a 400. CSV parsing errors and SQL table-read errors are wrapped as API exceptions instead of leaking raw stack traces to the client.

Pipeline Parity

Batch Pipeline vs. Single-Row Pipeline

Batch inference can compute statistics from a DataFrame, but single-movie inference must use saved global statistics to avoid schema drift.

01
Parse date fieldsBoth paths split release_date into month, day, year, day-of-week, and quarter, then repair two-digit years.
02
Recover missing rating signalsBatch mode can use group means from the request DataFrame; single mode reads global_stats.pkl for year/language fallback values.
03
Rebuild engineered ratiosBudget/runtime, budget/popularity, rating/popularity, totalVotes/year, and other ratios are rebuilt before model inference.
04
Align sparse one-hot columnsProduction requests are reindexed against features.pkl, adding absent one-hot columns as zero.

Conclusion

Project Synthesis & Roadmap

The project moves from notebook experimentation to a reusable prediction service without losing feature-engineering parity.

Modeling result: the notebook builds a high-feature regression workflow around log-transformed revenue, manual anomaly correction, external ratings/votes, JSON category processing, and a 10-fold blend of XGBoost, LightGBM, and CatBoost.

Production result: the app packages the model as a FastAPI service with batch, single-movie, and IMDb lookup prediction paths, saved feature schemas, optional Redis caching, PostgreSQL prediction logging, and Docker Compose deployment.

Future directions:

  • Add recorded CV and leaderboard metrics into the saved blend config for stronger model governance.
  • Move database credentials into environment variables for safer deployment.
  • Add automated tests for prepare_single parity against notebook feature output.
  • Track feature importance summaries for XGB, LGB, and CatBoost in the project page and API docs.
