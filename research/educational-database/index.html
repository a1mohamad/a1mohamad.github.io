Desktop Interface Overview

Application Scope

The project is a software-engineering application, not an AI model: the focus is clean desktop workflows and structured data management.

The Educational Database System is a C++ and Qt Widgets desktop app for managing common university-style records. It converts the earlier console database idea into a visual product with form inputs, table views, search boxes, report generation, login flow, user roles, and a consistent sidebar layout. The design goal is simple: make the data model usable through a real interface instead of command-line menus.

Primary UI shapeA single MainWindow organizes database, reports, users, and help areas through a left sidebar.
Data workflowEach record page follows the same pattern: inputs, Add, Update, Refresh, Delete, search, and table output.
Release goalThe project is not only source code; it has a GitHub release package for Windows users.
C++Implements the core entities, actions, validation logic, file loading, file saving, and application behavior.
Qt WidgetsBuilds the native desktop interface with dialogs, tab widgets, stacked pages, buttons, input fields, tables, and layout managers.
Table-Based ManagementRepresents stored records in searchable table views so the user can inspect and select rows visually.
Local PersistenceKeeps application data in local system files, making the app lightweight and easy to package without a server dependency.

Data Integrity

Validation, Refresh, and Search

A desktop database app needs predictable behavior around editing, reloading, and inspecting records.

Add
Create
read form → validate → append record
The add path takes the current form values and creates a new record only when the required identity fields are present.
Update
Edit
select row → edit fields → save
The update path lets the user correct existing information without removing and recreating a record manually.
Delete
Remove
select record → confirm intent → remove
The delete action is visually separated with a red button, which makes destructive operations easy to recognize.
Refresh
Sync
reload model → repaint table
Refresh provides a clean way to synchronize the table view with the current internal record state.

Software Engineering Readout

Why This Project Matters

The strength of the project is the bridge from basic C++ records to a usable desktop product.

This project matters because it demonstrates a different side of engineering from AI modeling: building a desktop interface, shaping a multi-entity data system, separating database records from user accounts, designing repeatable CRUD flows, embedding reports into the product, and shipping a Windows release. It shows that the portfolio is not limited to notebooks or model APIs; it also includes traditional software application development with C++ and Qt.
